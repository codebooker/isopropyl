# Rufus → ISOpropyl feature audit

This is the live product-parity audit for ISOpropyl. It compares the current
Linux implementation with Rufus master commit
[`2368e49a`](https://github.com/pbatard/rufus/tree/2368e49a82e854d3e702f824648cc723953dbb53)
(2026-08-24, including Rufus 4.15 changes). ISOpropyl is a Linux-native
AGPL-3.0-or-later implementation. Adapted data or behavior with upstream
copyright significance is identified in [third-party notices](THIRD_PARTY_NOTICES.md).

Status meanings:

- **Done** — implemented with automated non-destructive coverage. Physical-media
  certification may still be required for release confidence.
- **Partial** — a useful subset exists, or the backend is not yet fully exposed.
- **Planned** — feasible Linux work remains.
- **Research** — design, provenance, licensing, or hardware evidence is unresolved.
- **Policy** — an intentional safety/product rule.
- **Inapplicable** — a Windows implementation detail with no Linux counterpart.

| Raw `.img`/DD writing | **Done** | The GUI and headless CLI route plain, compressed, VTSI, virtual, and compressed-virtual inputs through one authenticated workflow with no `ImageWriter`/`dd` fallback. The root transaction holds one exclusive target descriptor, durably deactivates a 1 MiB front guard plus source/physical tail sectors, mandates inactive bulk read-back, activates tail then front guard, optionally performs a complete final hash, and identity-gates emergency deactivation. Unsupported or unknown target sector geometry now fails closed. Native/VM hot-swap, failure, and representative physical-media certification remain. |

FreeDOS publishes no detached signature, so the project pin is the trust anchor and the HTTPS live row is corroboration rather than publisher-signature verification. The exact LiteUSB image has additionally reached the FreeDOS kernel, FreeCom, and completed startup files in the repository's opt-in, networkless, snapshot-backed QEMU TCG/SeaBIOS harness. Scope is limited to fixed 32 MiB LiteUSB and 1 GiB FullUSB x86 images for BIOS or UEFI Legacy/CSM with Secure Boot disabled; there is no native UEFI, Secure Boot, ARM, or RISC-V path, and middle target capacity beyond the image is not erased, may retain previous data, and is not added to the image layout. Physical firmware/media certification and broader FreeDOS construction remain. |

## Priority order

1. Certify the unified GUI/CLI raw broker's installed PolicyKit/SCM_RIGHTS,
   failure/hot-swap, cache, VM, and physical-media behavior, then extend
   privileged exclusive target ownership across every destructive transaction.
2. Hardware-certify current UEFI/FAT32, UEFI:NTFS, and optional boot-time-validation modes and failure cleanup.
3. Certify and harden the default-off Syslinux developer transaction. The fixed
   root-owned helper, authenticated PREPARED/COMMIT/CANCEL protocol, kernel
   disk-generation binding, same-descriptor write/durability/read-back path,
   inactive-sector proof, sector-zero-last activation, authoritative app workflow,
   and retained locally reproduced QEMU/SeaBIOS bootstrap observation are
   implemented. A native hardened helper,
   installed PolicyKit/SCM_RIGHTS VM coverage, OVMF, hot-swap/failure tests, and
   physical certification still gate normal GUI exposure.
4. Hardware-certify the narrow immutable Casper layout and add only fixture-backed profiles.
5. Complete the gated Windows To Go preview through descriptor-bound privileged
   `wimlib` block apply, image-native BCD construction/read-back, offline SAN
   policy, and QEMU/OVMF plus physical-media certification before exposing it.
6. Add cryptographic Secure Boot trust and authenticated revocation data.
7. Complete FFU/VTSI/direct WIM/ESD and image-output formats.
8. Add project-owned signed manifests and corresponding-source-compliant hosting,
   then audited BIOS consumers for the dormant GRUB/Syslinux payloads; physically
   certify the explicit-consent UEFI Shell and FreeDOS workflows, and adopt
   detached FreeDOS publisher signatures if upstream makes them available.
9. Finish localization, conflict diagnostics, signed reproducible packaging, and
   physical certification of safe expert format controls.
